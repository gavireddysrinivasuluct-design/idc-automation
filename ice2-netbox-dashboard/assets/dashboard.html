How the rail groups are wired

One GPU tray, end to end — click any tray on the canvas below to load it here
Rail × scalable-unit matrix — every cell is one leaf switch; click to trace it
  • A rail is the set of all RDMAn ports (800G OSFP) across every tray. Port RDMA1 always goes to a rail-1 leaf, RDMA2 to a rail-2 leaf, and so on.
  • Rail leaves are numbered in blocks of four: rail 1 = BEL1–4, rail 2 = BEL5–8, rail 3 = BEL9–12, rail 4 = BEL13–16.
  • A scalable unit takes the k-th leaf of every rail: SUk = BELk, BELk+4, BELk+8, BELk+12. That is why SU1 uses BEL1 / 5 / 9 / 13 — one leaf from each rail block, not four neighbours.
  • Same port on all four leaves: a tray uses the same leaf port on each rail (gpu1256 → sw1p1 on BEL1, BEL5, BEL9 and BEL13), so tray position = port number.
  • Above the leaves: every leaf has 2 cables to each of the 36 spines, so GPU-to-GPU traffic on the same rail crosses at most one spine.

Design checks

  • Physical connections verified against the full NetBox backend cable list (2026-10-01): all 4,608 leaf–spine cables (73796–78403) and all 816 GPU RDMA cables (79002–79841) match port-for-port and cable-ID-for-cable-ID. SU2 has no backend cables recorded.
  • Full mesh: every one of the 64 leaves has 2 cables to each of the 36 spines on sw37–sw72 (4,608 cables), and every spine has 128 leaf-facing cables; spine port swN always faces leaf belN.
  • Rail-optimised: in each scalable unit, RDMA1–4 of every tray land on four different leaves (rail 1 = bel1–4, rail 2 = bel5–8, rail 3 = bel9–12, rail 4 = bel13–16). With 72 trays a leaf runs 72 down / 72 up, so it is non-blocking.
  • SU2 (bel2 / bel6 / bel10 / bel14) has no GPU cables. The inventory shows 70 trays gpu1328–1397 in racks A5–A8 with no cables at all — the likely missing unit.
  • Frontend: every tray's eth0 / eth1 (400G QSFP112) lands on a pair of NVIDIA SpectrumX leaves — SU1 → FEL1 + FEL2, SU3 → FEL5 + FEL6, SU4 → FEL7 + FEL8 (408 cables, all IDs match; NetBox resolved 2026-09-30). Pattern is eth0 → odd FEL, eth1 → even FEL on the same port.
  • Polarity exception: gpu1256 has eth0 → FEL2 swp1s0 (#83920) and eth1 → FEL1 swp1s0 (#83921), the reverse of the other 203 trays. Check the cabling or the NetBox record.
  • Out-of-band: BMC, OS MGMT and BF MGMT (1G) are recorded by cable ID for every tray (612 cables). Far ends are known only for gpu1256 (BF MGMT → OBL17 swp29, BMC → OBL18 swp29, OS MGMT → OBL17 swp1); the other 609 still need an export.
  • SU4 carries 60 trays, so its leaves have sw31–sw36 (12 lanes each) free.
  • The UFM pair attaches to the backend fabric on BEL59 / BEL60 / BEL63 / BEL64 on leaf port fnm1 for all four: UFM1 HCA1 → BEL60 fnm1, UFM1 HCA2 → BEL64 fnm1, UFM2 HCA1 → BEL59 fnm1, UFM2 HCA2 → BEL63 fnm1 (400G). NetBox still records these leaf ports as fnm0 and should be corrected; the UFM HCA1/HCA2 assignments keep the NetBox mapping and should be physically confirmed before the cable records are changed), with in-band Gi0/2 to FEL49 / FEL51, BMC and eth1 to OBL13 / OBL14, and eth2 back-to-back between the two UFMs.
  • Apart from the UFM ports on BEL59/60/63/64, leaves bel17–bel64 have spine uplinks but no downlinks recorded.
  • Spine and leaf models are not recorded against these hostnames; the site's spares are SN5610 (spine) and Q3400 (leaf). Trays gpu1400–1531 exist only in the cable data, not the inventory.
