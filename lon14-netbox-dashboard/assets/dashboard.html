How the rail groups are wired

One GPU tray, end to end — click any tray on the canvas below to load it here
Rail × scalable-unit matrix — every cell is one leaf switch; click to trace it
  • A rail is the set of all RDMAn ports (800G OSFP) across every tray. Port RDMA1 always goes to a rail-1 leaf, RDMA2 to a rail-2 leaf, and so on.
  • Leaves are numbered by scalable unit: SUk owns four consecutive leaves, BEL4k−3 … BEL4k (SU1 = BEL1–4, SU2 = BEL5–8, … SU16 = BEL61–64). Four SUs make a pod (pod 1 = SU1–4 = BEL1–16).
  • The rail is the position inside the SU block: rail r of SUk is BEL4(k−1)+r, so rail 1 = BEL1, 5, 9 … 61, rail 2 = BEL2, 6, 10 … 62, and so on. (ICE2 numbers the other way round: there an SU takes the k-th leaf of each rail block.)
  • Same port on all four leaves: a tray uses the same leaf port on each rail (gpu1 → sw1p1 on BEL1, BEL2, BEL3 and BEL4), so tray position = port number. Hosts are normally numbered by position (gpuN in SU⌈N/72⌉, slot ((N−1) mod 72)+1); exceptions are outlined in amber.
  • Above the leaves: every leaf has 2 cables to each of the 36 spines (leaf port sw(73−i)p(3−M) ↔ spine i port swjpM), so GPU-to-GPU traffic on the same rail crosses at most one spine.

Design checks

  • NetBox (site lon14, sys1-lon14 InfiniBand fabric): 4,608 leaf–spine cables (#95536–100229) and 4,608 GPU RDMA cables. Every leaf has 72 GPU downlinks and 72 spine uplinks, so all 16 SUs are fully cabled (1,152 trays).
  • Full mesh: every one of the 64 leaves has 2 cables to each of the 36 spines on sw37–sw72; leaf j port sw(73−i)p(3−M) faces spine i port swjpM (4,608 / 4,608 cables follow this rule).
  • Rail-optimised: RDMA1–4 of every tray land on the four leaves of its SU (rail r = BEL4(k−1)+r). With 72 trays a leaf runs 72 down / 72 up, so it is non-blocking.
  • Host placement: 45 trays are not at the position their number suggests (gpuN → SU⌈N/72⌉ slot ((N−1) mod 72)+1), most of them in SU11; their four rails still agree, so this is host numbering, not miscabling. They are outlined in amber. gpu1153 holds gpu118's position (SU2 slot 46) and gpu118 has no backend cables: confirm which host is really there and fix the NetBox record.
  • Frontend: every tray's eth0 / eth1 (400G) lands on a pair of SpectrumX FEL leaves, eth0 → odd FEL, eth1 → even FEL on the same port (2,304 cables, no crossed pairs). BF MGMT / BMC (1G) go to OBL leaves (2,304 cables).
  • The UFM pair (UFM Gen 3.5, 10.2.64.75 / .76) attaches to the backend fabric on leaf port fnm1: UFM1 ib0 → BEL16, ib1 → BEL32; UFM2 IB0 → BEL12, IB1 → BEL28. Their BMC / eth1 go to OBL154 / OBL155 and the consoles to CON13; no frontend link is recorded.
  • The Ethernet fabric at the same site (sys2-lon14, SN5610) is not part of this dashboard.
